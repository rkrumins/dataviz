# Provider architecture uplift: FalkorDB decoupling → provider catalog/contract → ArcadeDB (OpenCypher)

## Context

The app has one de-facto graph provider: `backend/app/providers/falkordb_provider.py` — **11,333 lines**, 163 methods, 222 commits of churn — plus three FalkorDB satellites (`falkordb_connection.py` 1,929, `falkordb_deep_search.py` 3,604, `falkordb_materialize.py` 2,552). Neo4j (2,699 lines) and Spanner (2,747) live apart in `backend/graph/adapters/` and duplicate the algorithms; Neo4j is missing top-level browse and the Lens walk. Adding a provider today means editing ~22 scattered sites (two duplicated `if ptype ==` dispatch chains, a string-keyed capability dict, a DB CHECK constraint, 15 frontend enumerations) and satisfying three **undeclared** contracts (duck-typed ontology-injection setters, the manager's `preflight`/`inflight_ops`, the `DeepSearchProvider` protocol).

Goal: make "add a graph data provider" one consistent registration; decouple FalkorDB so its dialect-neutral algorithms become a shared **Cypher-family base written in standard OpenCypher**, with each dialect provider overriding only what differs or what it can do faster; then ship **ArcadeDB** (native OpenCypher over its HTTP API) as the second client with full user-facing parity (browse, search incl. deep search, edges, lineage, writes, stats, schema discovery, health, aggregated roll-ups, trace v2, the Lens walk), onboardable from the Admin UI, with Docker + demo data. Spanner is out of scope (kept working, not touched beyond registration). Neo4j is a documented follow-up on the same base. GraphQL/DataHub is ignored for now. The strategic requirement is **extensibility to any future OpenCypher/Cypher provider** (Neo4j, Memgraph, Kùzu, Apache AGE, …): adding one must be "an executor + a dialect + a descriptor (+ method overrides only where that dialect differs)", proven by a reusable **provider conformance kit** (fake-executor unit suite for the base, the live contract-snapshot harness, and a dialect conformance suite) and a written recipe.

## Decisions (confirmed with the user)

**Scope: FalkorDB and ArcadeDB only.** Neo4j, Spanner and DataHub are not modified — they are registered in the new catalog so they keep working exactly as today (their existing tests stay green), and Neo4j's migration onto the Cypher base is a documented follow-up, not part of this work.

| Decision | Choice |
|---|---|
| Cypher family | Shared `CypherGraphProvider` base; **FalkorDB is client #1** (its refactor introduces the executor/dialect seams), **ArcadeDB client #2**; Neo4j migration = documented follow-up |
| Override model | Base implements every contract method in **standard OpenCypher**; dialect providers **override** methods where their Cypher differs structurally or they have a native fast path; a thin `CypherDialect` object only for fragment-level differences (DDL, introspection procedures, id/label functions, timeout injection) |
| Extensibility | Cypher family only for now (GraphQL ignored). Every new Cypher provider = `CypherExecutor` impl + `CypherDialect` + `ProviderDescriptor` (+ overrides), validated by the conformance kit; the recipe lives in `DEVELOPER_GUIDE.md` |
| ArcadeDB feature tier | **Full parity incl. deep search and `trace_closure`/`trace_closure_coarse`** |
| Admin UI | Backend-served type catalog (`GET /api/v1/admin/providers/types`) + ONE frontend `providerTypes` module replacing the 15 sites |
| Delivery | One worktree, **three stacked PRs** (PR1 FalkorDB decoupling → PR2 contract/catalog/UI → PR3 Cypher base + ArcadeDB + Docker + demo) |
| Transport for ArcadeDB | HTTP/JSON via `httpx` (already a dependency), `language: "opencypher"` (never the deprecated Gremlin-translated `cypher`); executor seam allows a Bolt executor later |

## ArcadeDB facts the design relies on (verified against current docs, release 26.8.1)

- HTTP API `/api/v1/`: `GET /ready` (204), `GET /databases`, `POST /server {"command":"create database X"}`, `POST /query/{db}` (reads) / `POST /command/{db}` (writes) with `{language, command, params, limit, serializer: record|graph|studio, retries}` → `{"result": [...]}`; `POST /begin|commit|rollback/{db}` + `arcadedb-session-id` header (30 s idle expiry); `POST /batch/{db}` NDJSON bulk import (`@type/@class/@id/@from/@to`, returns `idMapping`). Basic auth `root`; errors `{error, detail, exception}`.
- Native OpenCypher engine (97.8% openCypher TCK): MATCH/OPTIONAL MATCH/UNWIND/MERGE ON CREATE|MATCH/SET +=/DETACH DELETE/FOREACH/UNION/CALL {} subqueries/CALL procedures/CASE/list comprehensions/map projections/`$params`/variable-length paths; `id()`, `labels()`, `type()`, `keys()`, `properties()`, `coalesce`, `toLower`, `collect`, `count`; `CALL db.index.fulltext.queryNodes('T[p]', q) YIELD node, score`.
- Known differences: **identifiers are case-insensitive** (`:T2` ≡ `:t2`), **types must be declared before insert** (`CREATE VERTEX TYPE X IF NOT EXISTS`, `CREATE EDGE TYPE Y IF NOT EXISTS`), indexes via SQL DDL `CREATE INDEX ON T (p) UNIQUE|NOTUNIQUE|FULL_TEXT`, introspection via `SELECT FROM schema:types|schema:indexes`, RIDs are strings (`#9:0`), no `USING INDEX` hints, no documented `REMOVE`.
- Docker: `arcadedata/arcadedb:26.8.1`, port 2480, `ARCADEDB_SETTINGS="-Darcadedb.server.rootPassword=… -Darcadedb.server.defaultDatabases=…"`, `ARCADEDB_OPTS_MEMORY`, volume `/home/arcadedb/databases`.
- **Day-0 spike (must be run live before PR3 code is written; each answer selects a plan branch):** does Cypher `CREATE (:Label)` auto-declare the type or error; does `MATCH (n:Unknown)` error or return empty; is `count(*)` per type O(1); exact JSON row shape for `RETURN n, r, m` with `serializer: "record"`; list-valued params in `IN $urns`; `id(n)` value shape; MERGE on a UNIQUE index violation; whether a multi-statement `save_custom_graph` batch needs an explicit `/begin` session; HTTP timeout vs `command.timeout` behaviour.

## Architecture (target state after PR3)

```
backend/common/interfaces/provider.py        GraphDataProvider (formal contract: reads/writes + ontology-injection
                                             setters + lifecycle as base members; CursorMismatchError; capabilities)
backend/common/providers/                    shared kernel (existing: trace_orchestrator, aggregation, ancestor_cache,
                                             schema_introspection, deadlines, config, pair_rules, identity)
                                             + NEW: catalog/ package (ProviderDescriptor registry, one module per
                                               type), rowmap.py, cursors.py (extracted from FalkorDB, re-exported
                                               from the old private names)
backend/common/providers/cypher/             kernel-level seams only: executor.py (CypherResult + CypherExecutor
                                             Protocol), dialect.py (CypherDialect dataclass) — no app imports
backend/app/providers/cypher/                CypherGraphProvider base = FalkorDB's G/GF mixins lifted unchanged
                                             (they lazily import app-layer modules — backend.app.config.resilience,
                                             services.ontology_levels/node_identity, fastapi — so the base lives in
                                             the app layer, not under common/ or graph/adapters/); + deep_search/,
                                             materialize.py (ScanStrategy seam), closure/trace/aggregation as lifted
backend/app/providers/falkordb/              FalkorDBProvider(CypherGraphProvider): ConnectionMixin (the 5 query
                                             chokepoints, retries/failover/quiesce/telemetry), FalkorDBExecutor,
                                             FalkorDBDialect, overrides = Redis caches/ledger, projection graph,
                                             cluster, reduce_count counts, warmup, GRAPH.LIST …
backend/app/providers/falkordb_provider.py   thin compatibility re-export (every public + currently-imported name)
backend/app/providers/arcadedb/              ArcadeDBProvider(CypherGraphProvider): client.py (httpx), dialect.py,
                                             schema.py (type/index bootstrap via SQL DDL), provider.py, descriptor.py
backend/graph/adapters/neo4j_provider.py     unchanged (follow-up: BoltExecutor + Neo4jDialect on the base)
backend/graph/adapters/datahub_provider.py   unchanged (read-only stub; out of scope)
```

Principles: (1) base = standard OpenCypher; overrides only where a dialect differs or is faster; (2) one `ProviderDescriptor` per type is the single registration point (type id, family, label, capabilities, connection shape, validation, probe strategy, `build()`); both legacy dispatch entry points delegate to it; (3) capabilities are explicit flags consulted by endpoints instead of `provider_type ==` / `isinstance` / catching `NotImplementedError`; (4) behaviour preservation for FalkorDB is proven by the contract snapshot + unit suite + live probes before/after every step.
